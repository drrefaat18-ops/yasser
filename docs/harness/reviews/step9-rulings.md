# STEP 9: rulings made during execution

Decisions Claude took where the plan was silent, contradictory or wrong. The STEP 9 Codex review sees this file.

| ID | Task | Ruling | Why | Cost if wrong |
|---|---|---|---|---|
| R1 | 9.1 | A project with no `figures.json` may build only when its `rework` receipt is history-imported (plan N2); it keeps the legacy figure path (SVG link → PNG mirror in `<figures>/png/`) and the receipt records `figures: legacy`. Any other project fails with `FIG-MANIFEST`, and `figures.json` is now a required rework output, so a harness book cannot reach build without one. The medical project gets no manifest. | The plan's note "the medical figures are `raster.existing`" cannot hold: its chapters link `.svg` files whose embedded bytes are the PNG mirrors, so a manifest would mean editing imported chapters (DEC-035 scope lock) or re-rasterising (a new DOCX, breaking the STEP 6 golden). | One legacy branch, reachable only by the one imported book. |
| R2 | 9.1 | `test_png_300dpi_at_text_width` compares the rounded dpi. | PNG stores pixels per metre: 300 dpi is written as 11811 px/m and read back as 299.9994. | None. |
| R3 | 9.1 | A chapter places a figure with `![](fig:<id>)`. Caption, alt text, credit and licence come from the manifest; the number is computed (`caption_pattern` with `{chapter}` = the chapter's position in `chapter-plan.json`, `{n}` = order of first placement). The builder writes the alt text to `wp:docPr/@descr` and prints the credit under the caption; `assemble` rewrites `fig:` links to the render with a `Figure c.n — caption` alt. In a manifest project, a direct image link in a chapter is `FIG-UNKNOWN` (it would bypass caption, alt and licence checks). | The spec fixes numbering and the manifest fields but not the reference syntax. `fig:` is already skipped by the asset checks (a URI scheme). | Authors write `fig:` links instead of paths. |
| R4 | 9.1 | New check ID `FIG-MANIFEST` for manifest-level problems: file missing or not JSON, schema errors other than the caption/alt/licence/credit fields (those keep their own IDs), duplicate id, `chapter_id` not in the plan, kind/status mismatch (`raster.existing`↔`existing`, `author-asset`↔`needs-author-asset`, else `generated`), a source in the wrong place, and a pack that is unknown, not in `brief.figures.packs`, or not ready. It blocks the build. | Core §7.3 lists per-figure IDs only; these defects need a name and must block. | One extra ID in the report. |
| R5 | 9.1 | Manifest `source` paths are project-relative. Generated kinds must sit under `<paths.figures>/src/`; `raster.existing` under an allowed asset root and not in `out/`. | Core §7.1 says "under `figures/src/`" or "under an allowed asset root" without a base. | None. |
| R6 | 9.1 | `render.py` and `check_figures.py` CLIs are gated dry runs: they render into a temporary folder and print. `run build` is the only writer of `<figures>/out/`, which it clears first. | Same as step8 R32: a second writer would change build outputs outside a receipt. | None. |
| R7 | 9.1 | `FIG-RESOLUTION` measures dpi at the width the builder places the raster at, from one shared function `figures.placed_width_cm` (text width capped at 14 cm; tall figures, h/w > 0.9, at 10 cm). The legacy branch uses it too; DOCX EMUs are unchanged. | The spec says "at placed width"; two copies of the placement rule would drift. | None. |
| R8 | 9.1 | Charts: the source draws on matplotlib's current figure; its `figsize` gives the aspect ratio, the harness sets the width to `theme.layout.text_width`. SVG hash salt `harness`, text as text, no date/creator; the PNG is resized (LANCZOS) to the exact placed pixel width when matplotlib's canvas rounding is off by a pixel, then canonical-encoded. Hand SVGs: an HTML page with the SVG filling the viewport, headless Edge/Chrome with a throwaway profile, then the same exact-width resize. | Deterministic, exact-width output; a user's open browser profile must not be touched. | None. |
| R9 | 9.1 | `build-report.json` gains `figure_checks` (the checker-report checks), `figure_renders`, `figure_versions` (Pillow, matplotlib, browser, RDKit as used) and `chem_unverified`. The checker report is one check per ID with `measured {count, figures[]}`. | Plan: versions are recorded in the build report; the audit reads `chem_unverified`. | None. |
| R10 | 9.1 | `tests/helpers.temp_repo` copies and commits the repo's `.gitignore`. | `build` tool_paths now list directories (`harness/figures`, `harness/presets`); without the ignore rule, a `__pycache__` written by the run made the tool "dirty". The real repo ignores it already. | Test helper only. |
| R11 | 9.1 | `build` tool_paths gain `harness/figures`, `harness/schema.py` and `harness/schemas/figures.v1.json`. `figures.v1.json` needed no field change. | N9: every non-control-plane file the stage executes. | None. |
| R12 | 9.1 | The positive-config generator gives each fixture a manifest (`raster.existing` ball) and a `fig:ball` link. | `figures.json` is a required rework output (R1); the fixtures complete rework in tests. | None. |
| R13 | 9.2 | `HARNESS_OFFLINE` set in the environment makes cross-checks run offline (`unverified`). Builds are `live` by default. | Tests must not reach PubChem, and a build test cannot pass a mock into a subprocess. The switch only ever weakens a result to `unverified`, which blocks `complete audit`, so it is not a bypass. | None. |
| R14 | 9.2 | The PubChem cache lives in `<figures>/.cache/pubchem/`, is keyed by the SHA-256 of the request URL, holds only parsed successful answers and is neither a build input nor output. | Core §7.5 names the folder; a cache written during the build cannot be one of its hashed inputs. | A stale cache entry would need deleting by hand. |
| R15 | 9.2 | Only `chem.structure` is cross-checked (`CROSSCHECK_KINDS`); a reaction has no single compound to look up. Reaction `conditions` are not drawn (they belong in the caption). | Core §7.5 describes the cross-check for `name`/`pubchem_cid`, which only structures have. | Reaction participants are not checked against PubChem. |
| R16 | 9.2 | The cross-check compares stereo-free canonical SMILES (both sides canonicalised by RDKit), `pubchem_cid` before `name`, and accepts PubChem's old and new property names (`CanonicalSMILES`, `ConnectivitySMILES`, `IsomericSMILES`, `SMILES`). An unreadable answer is `unverified`. | PubChem renamed its SMILES properties in 2025; raw string comparison of two canonical forms from different toolkits would report false mismatches. | A stereo-only error is not caught. |
| R17 | 9.2 | `chemistry.preflight()` also reports an installed RDKit that differs from the pin in `requirements-chemistry.txt` (`rdkit==2026.3.6`); the figure is then `FIG-MANIFEST` (pack not ready). | Byte-identical renders hold only for the pinned version. | An upgrade needs a pin change and new evidence. |
| R18 | 9.2 | An audit `fixes.md` row clears `CHEM-UNVERIFIED` only if `ID` is the figure id, `status` is `ruled by user` and its `DEC` cell cites a DEC that exists in the project's `decisions.md`. | Core §7.5 "cites a DEC"; any text in the cell would otherwise pass. | None. |
| R19 | 9.2 | Chemistry drawings: CoordGen layout, bond length 110 px and font 44 px at 300 dpi, canvas height 0.42 (structure) or 0.26 (reaction) of the text width. | Legible at the placed width with modest white space (evidence PNGs). | Cosmetic. |
